# Design: harness-package

## Purpose

The bench's page driver becomes a package that cannot reach the engine: everything it knows about the world it reads from the bench's routes, strata's part is hosting a bench for it and a typecheck that the engine's route bodies still match what the driver declares, and a headed run is stepped by the operator one action at a time.

## Form

A bun workspace package `harness/` holding the driver now under `src/player/`, a served subkind route on the bench, a thin strata adapter under `src/adapter/`, and a hold before each action of a headed run.

1. Layout. The root package.json gains `"workspaces": { "packages": ["harness"], "catalog": { <playwright, zod and @voidwire/apiconf at today's exact versions, package.json:18-20> } }` and a dependency `"harness": "workspace:*"`; every manifest that needs one of those three names it as `"catalog:"`, so each version has one home (the root keeps playwright for tests/page.test.ts:5 and zod for the engine); its scripts `player` and `score` become `harness` (`bun run src/adapter/main.ts`) and `score` (`bun run src/adapter/score.ts`). `harness/` holds its own `package.json` (name `harness`, `"exports": { "./*": "./src/*" }` so strata imports a module as `harness/<module>.ts`, its dependencies from the catalog, its own scripts `typecheck`, `check` and `test`), its own `tsconfig.json` (the root's compiler options, `include` only `src/**/*.ts` and `test/**/*.ts` inside `harness/`), `src/` and `test/`; its devDependencies typescript, bun-types and @biomejs/biome come from the same catalog, which holds them at the root's versions. One `bun.lock` stays at the root, and bunfig.toml pins `[install] linker = "hoisted"`, the layout strata installs with today, since a new workspace otherwise installs isolated and puts the member's dependencies under harness/node_modules (docs/work/harness-package/shape/linker-probe.txt); hoisted keeps every dependency of both packages in the root's node_modules. Every file of `src/player/` moves under `harness/src/` (`candidates.ts`, `page.ts`, `jev.ts`, `words.ts`, `goal.ts`, `target.ts`, `rule.ts`, `run.ts`, `score.ts`, `main.ts`), and `src/player/` is removed. The word "player" leaves every name the move touches: the package is `harness`, the bench page's driver; `runPlayer` becomes `drive`, `PlayerOptions` becomes `DriveOptions`, `PLAYER_FLAGS`/`PLAYER_USAGE` become `RUN_FLAGS`/`RUN_USAGE`, the tmp dir prefix `strata-player-` becomes `strata-harness-`. `RULE_AUTHOR`'s string, `T_DONE`, `T_ACT`, the sweep's grid and method, and every field of `run.json`, `loops.jsonl`, `events.jsonl`, `received.jsonl` and `<set>.score.json` keep their names and values (src/player/rule.ts:24-27, run.ts RunRecord and LoopRecord). `src/driver/` (the fuzzer) is untouched; it imports nothing from `src/player/` today.

2. The boundary. No file under `harness/` names a path outside `harness/`: its imports are its own relative files, `node:` modules and its declared dependencies. That is made structural by a strata-side test, `tests/harness-boundary.test.ts`: it copies `harness/` without any `node_modules` of its own, alone, into a fresh temporary directory with nothing beside it (the files on disk, since the gate's first run in a job's worktree comes before anything is committed, verify.ts:328), links the root's `node_modules` into the copy as its `node_modules` (the dependencies the workspace installed, and no strata source), and runs the package's own `bun run typecheck` and `bun test` there; both must exit 0. An import of `../src/engine/...` or `../../src/server/...` from any harness file then names a path that does not exist, and the copy's typecheck fails. An absolute path still resolves from the copy (docs/work/harness-package/shape/boundary-probe.txt: the absolute import type-checks, exit 0), so the test also runs the copy's `tsc --listFilesOnly -p tsconfig.json` and requires every file it lists, by real path, to lie under the copy or under the linked node_modules' real path; a file anywhere else fails the test naming it. ember's gate also plans `typecheck(harness)`, `lint(harness)` and `tests(harness)` in `harness/`'s own directory and keeps `harness/` out of the root's test run (verify.ts:287, 545-560), so the package's own checks run on every push; the copy test is what makes an engine import fail, since inside the repository a relative path out of `harness/` still resolves on disk.

3. The bench's routes the harness reads (`harness/src/bench.ts`, new). One module declares the bodies the harness reads, each as a TypeScript type over only the fields it uses, and the one GET helper (`getJson`, moved from goal.ts:34 unchanged, casting as today): `VerbsBody = { verbs: { verb: string; fields: string[] }[] }` from `/api/verbs`; `SubkindsBody = { subkinds: { subkind: string; kind: string }[] }` from `/api/subkinds`; `SnapshotBody` from `/api/snapshot`, the items with each `holder`, the people with each `location` (a room or a transit), and `pending`, each `{ opened: { id, subkind, actor, targets, payload }, due: { at, fires, after }, resolutions: { by, action, after }[] }` with `After = { holders: Record<string, string>; locations: Record<string, Location> }`; `EventsBody = { events: Event[] }` from `/api/events`, `Event` the envelope fields it reads (`id`, `seq`, `subkind`, `kind`, `actor`, `targets`, `payload`); `ReceivedBody = { thing: string; copies: unknown[] }` from `/api/received/<person>`. `afterOf(snapshot)` is written here over `SnapshotBody`'s items and people, as the engine's at src/engine/pending.ts:49 is over its Snapshot; the engine keeps its own for `pendingOf`, so the projection is computed on both sides of the route, and the contract typecheck (section 6) holds the two shapes together.

4. Every engine fact read over a route instead. `target.ts` stops importing `verbs()`, `subkinds` and `kindOf`: the run reads `/api/verbs` and `/api/subkinds` once, at its start, before the target, and the verbs list travels in the goal (`Goal` gains `verbs: VerbsBody["verbs"]`, `vocabulary()` gains the served subkinds); `fieldsOf(verb)`, `writesWords`, the prompt's verb lines and `stepAction` (rule.ts:173) read the served verbs; `speechKinds` is the served subkinds whose `kind` is `speech`; `checked()`'s refusal for a speech kind names the bench ("the bench serves no speech kind ...") in place of the registry. `rule.ts` and `goal.ts` take `Event`, `Pending`, `Opened`, `After` and `SnapshotBody` from `bench.ts`. `run.ts` takes `SnapshotBody` from `bench.ts`. A failed read of `/api/verbs` or `/api/subkinds` stops the run as a bench stop at call `target`, the shape every other route failure already has (run.ts benchStop).

5. The served subkinds (`src/server/routes.ts`). `GET /api/subkinds` answers `{ subkinds: subkinds.map((subkind) => ({ subkind, kind: kindOf(subkind) })) }`, built from the registry's keys (events.ts:75) and `kindOf` (events.ts:116), the one home of both, in registry order; nothing states a subkind or a family a second time and `rule()` is unchanged. routes.ts exports a type per body it serves (`VerbsBody`, `SubkindsBody`, `SnapshotBody` as today, `EventsBody`, `ReceivedBody`), and each GET handler builds its body as that type (`satisfies`), so the exported types are the bodies the bench serves. The page (`bench/`) does not read the new route.

6. strata's adapter (`src/adapter/`, new). `host.ts`: `hostBench({ worldDir, tickMinutes })` boots a fresh bench through `startServer` on an ephemeral port over a database in a new temporary directory and returns `{ ok: true, base, stop }` (stop closes the server and removes the directory) or `{ ok: false, message }` from boot's refusal: the code now at run.ts:353-368, moved. The harness's `DriveOptions` gains `host?: (bench: { worldDir: string; tickMinutes: number }) => Hosted`; `drive` with no `url` calls it, a refusal stops the run as kind `boot` as today, and with neither `url` nor `host` the run stops at once as kind `boot` naming that it has no bench to drive. `contract.ts`: type-level checks, compiled by the root typecheck and run by nothing, that each body type routes.ts exports is assignable to the harness's declared type of the same route (`VerbsBody`, `SubkindsBody`, `SnapshotBody`, `EventsBody`, `ReceivedBody`), so a route change that would break what the harness reads fails strata's typecheck; this is the goal typing against the API. `main.ts` and `score.ts`: each one line over the harness's own command line, `await cli(Bun.argv.slice(2), { host: hostBench })` and `await scoreCli(Bun.argv.slice(2), { host: hostBench })`. The harness's `main.ts` and `score.ts` export those functions (the argument parsing and exits now at src/player/main.ts and score.ts:212-261, unchanged in flags and messages), each also runnable on its own, where the run needs `--url` and `score` stops naming that each goal needs a hosted bench.

7. Step-through (`harness/src/run.ts`). `DriveOptions` gains `hold?: (action: string) => Promise<"go" | "end">`. A headed run with no `hold` given uses `holdOnEnter`: it prints `hold: press Enter to perform "<action>"` and resolves `go` on the next line read from stdin, `end` when stdin has ended. A headless run holds never: `hold` is not called. In each loop the order is: read, ask, decide, `printLoop` (the state text, every question with its answer, held, the decision and the chosen action, run.ts:241-266, unchanged), append the loop to `loops.jsonl`; on reached or stuck the run ends there with no hold, since no action follows; otherwise the plan's `pressedAfter` read, then the hold, then `perform`. An `end` stops the run with outcome `stopped`, kind `hold`, call `loop <n>`, the action not performed, and the run's files written as any stop writes them. `score --headed` holds the same way before every action of every goal; there is no timing number anywhere.

8. Tests. The harness's own tests (`harness/test/`) run with only `harness/` present: the rule (`decideLoop`, `nextMove`, `choose`, `advanced`) over typed fixtures, `checked()` and `vocabulary()` over a fixture `PageRead` and served verbs and subkinds, `writesWords` over served verbs, `satisfies` and `afterOf` over a fixture snapshot body, `holds` against a local `Bun.serve` stand-in answering fixture bodies on `/api/snapshot` and `/api/events`, and `holdOnEnter` over a stand-in stdin (a line gives `go`, an ended stream `end`). The tests that drive the real bench stay strata-side under `tests/` (player, score, page, rule), importing the harness package by name and hosting through `src/adapter/host.ts`; their claims and assertions are unchanged except the renamed names, the said refusal's wording ("the bench serves no speech kind"), and new cases: a headed run with an injected `hold` calls it once per performed action, after that loop's print and before the page changes, and performs nothing after an `end`; a headless run never calls it; `/api/subkinds` answers every registry subkind with its family; a run whose `/api/subkinds` answers 500 stops as a bench stop at `target`.

9. Proof that the move changed nothing it should not. The committed calibration score is the rule's from before pending-states (last written at 0e31a2a, an ancestor of cd700c7; docs/work/pending-states/design.md:50), so it is no baseline for this move. First, before any move code lands, the job runs `bun run score --goals corpus/goals/calibration.json --sweep --tick-minutes 10` on the unmoved code in its worktree with the real endpoints and commits that score file and its runs as a commit of their own: the baseline. A baseline whose sweep best is not T_DONE 0.6, T_ACT 0.3 halts the job to the orchestrator before any move code, since that is pending-states' unswept constants meeting their first sweep, not this move's; this job changes no constant. blind-2's committed score, made at 4a48f97 with no change under src, bench, world or tests since, is its own baseline. After the move: `bun run score --goals corpus/goals/calibration.json --sweep --tick-minutes 10` and `bun run score --goals corpus/goals/blind-2.json --tick-minutes 10` run again with the real endpoints, their score files and runs committed. calibration must hold the baseline's held count with its sweep's best at the baseline's pair, and blind-2 12 of 13, as corpus/goals/blind-2.score.json records. A count that differs fails: for each goal whose held differs from its baseline run, the builder names the first loop whose decision kind or chosen candidate departs from the baseline run's loops.jsonl and what decided it; a departure code decided (reached, resolve, wait, plan, stuck on a missing move, or the target and vocabulary check) is a regression the move fixes before anything merges, and one under `choose()` over Jev's nouls or from a different model target is non-reproducibility, which halts to the orchestrator with both runs named and merges nothing until ruled.

Acts on the gap: It supplies the package the gap names, a harness whose engine and server imports cannot resolve because it is checked and tested copied out alone, reading verbs, speech kinds, pending states, the snapshot and the history over the bench's routes with one new route serving the subkinds from their home; and it supplies the hold, a wait on Enter after each loop's print and before its action, in every headed run.

## Commitments

- No file of the harness package names a path outside it; copied alone beside only its installed dependencies, it type-checks and its tests pass, so an import of the engine or the server cannot resolve.
- Every fact the harness uses about verbs, their fields, speech kinds, pending states, the snapshot and the history is read from a bench route during the run; the harness holds no copy of an engine table.
- The bench serves the subkinds with their families from the registry and kindOf, their one home; nothing states a subkind or a family a second time.
- strata's adapter is the bench host and a typecheck that the bodies the bench serves satisfy what the harness declares for each route it reads, and its command lines are one call each into the harness.
- A headed run prints each loop whole and then performs nothing until the operator presses Enter; a headless run never waits on the operator; there is no timing number.
- The rule, the typed plan, pending resolution, reached by the code check, T_DONE and T_ACT, and every corpus file's fields are unchanged; calibration holds the held count and best pair of a baseline scored on the unmoved code, and blind-2 the count its committed score file records.
- Every dependency version the root and the harness share has one home, the workspace catalog.
- The fuzzer under src/driver is unchanged.

## Sacrifices

- The harness's tests that drive a real bench live strata-side, since a real bench is strata's; the package's own tests prove its logic over fixtures and stand-ins, and the end-to-end claims are proved where the bench is. (4 of 17 tests/*.test.ts)
- The harness's declared route bodies are cast, not parsed, as today; a body the bench serves wrongly at run time surfaces as a wrong decision or a thrown read, and drift is caught at strata's typecheck, not at run time. (0 of 48 corpus/runs/*/run.json)
- Jev and the model are not deterministic, so the re-scored calibration and blind-2 counts can differ with no code change; a differing count halts for a ruling rather than passing or being re-run until it matches. (not a case: It bites only in this job's two re-scores, where a differing count halts for a ruling; no usage path re-scores a set to compare it.)
- A headed run cannot be left unattended: it waits on Enter before every action, and a headed score run waits before every action of every goal. (1 of 48 corpus/runs/*/run.json)
- The projection of a snapshot to its item holders and person locations is computed by the engine for pending afters and by the harness over the served body; the contract typecheck holds their shapes together, not their code. (not a case: A structure of the code, two projections of one served shape held together by the contract typecheck; no run or usage exercises it as a case.)
- Calibration is scored twice in the job, a baseline on the unmoved code and again after the move, so the job pays two calibration runs to the real endpoints. (not a case: A one-time cost of this job's proof, two calibration runs of nine goals each to the real endpoints, never paid by a later run.)

## Risk

If the boundary test linked anything but the installed dependencies into the copy, an engine import could resolve through it and the boundary would be prose again; it links only the root's node_modules, which holds no strata source, and the listed-files check catches an absolute path the copy alone would still resolve. If calibration were compared with its committed score, a goal pending-states changed would read as the move breaking the rule, which is why the baseline is scored on the unmoved code first. If contract.ts checked the harness's types against themselves rather than against the types routes.ts builds its bodies as, a renamed field would pass; the routes build each body as its exported type, and a mutation renaming a served field must fail the root typecheck. If the hold came before printLoop, the operator would press Enter blind; the order is print, append, hold, perform. If verbs were read on every loop rather than once, a run would make one more request per loop for a fact that does not change during a run. If the re-scores differ by noise and the builder re-runs until they match, the score files stop being evidence, which is why a differing count halts.
