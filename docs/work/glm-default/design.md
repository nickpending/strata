# Design: glm-default

## Purpose

The player's default model becomes z-ai/glm-5.3-flash, asked by json_object and served only by Z.AI with no fallback, under a request name of its own, while every other model, Haiku included, is asked by the json-schema-retry request byte-identical. Every model call records the provider OpenRouter reported, carried into score and compare; compare sets each model beside the other under its own request; a run directory is claimed atomically so concurrent scores never collide; run.json records the world relative to the repository root (#8); a score with no model named lands on the default's named path, so no committed score file is ever written over. GLM and Haiku are then re-scored on all four sets under corpus/experiments/glm-default/ beside byte-identical copies of the goal files, and compared there.

## Form

One request table in words.ts read by every place that names a request, one provider field from the attempt to the compare, one atomic run-directory claim, one relative world path, then one measured comparison in an experiment folder.

1. The request table (`harness/src/words.ts`, extending `complete()` at words.ts:120). `DEFAULT_MODEL` (words.ts:13) becomes `"z-ai/glm-5.3-flash"`. `REQUEST` (words.ts:19) is replaced by a typed table: `type Request = { name: string; body: (model: string, prompt: string, schema: z.ZodType, name: string) => Record<string, unknown> }`. `JSON_SCHEMA_RETRY` has name `"json-schema-retry"` and builds exactly today's body, the same keys in the same order: `{ model, messages: [{ role: "user", content: prompt }], response_format: { type: "json_schema", json_schema: { name, strict: true, schema: wireSchema(schema) } }, provider: { require_parameters: true }, usage: { include: true } }`. `JSON_OBJECT_Z_AI` has name `"json-object-z-ai-retry"` and builds arm F's body (corpus/experiments/glm-request/tools/proxy.ts:142 and :165): `{ model, messages: [{ role: "user", content: prompt }], response_format: { type: "json_object" }, provider: { order: ["z-ai"], allow_fallbacks: false }, usage: { include: true } }`, with no require_parameters, since Z.AI lists response_format and not structured_outputs (tools/endpoints.json). `REQUESTS: Readonly<Record<string, Request>> = { "z-ai/glm-5.3-flash": JSON_OBJECT_Z_AI }`, and the exported `requestFor(model: string): Request` returns `REQUESTS[model] ?? JSON_SCHEMA_RETRY`, so every model not listed, Haiku included, gets today's request. An exported `modelOf(options: ModelOptions): string` is `options.model ?? DEFAULT_MODEL`, the one place the default is applied. complete() builds its body once with `requestFor(modelOf(options)).body(...)`; the parse, the one identical retry on a parse refusal and the refusals are unchanged. The prompts are unchanged.

2. The provider (`harness/src/words.ts` attempt() at words.ts:98, `harness/src/run.ts` Call at run.ts:135 and recordAttempts() at run.ts:572). `Attempt` gains `provider: string | null`, the chat completions body's top-level `provider` when it is a string, else null. `Call` gains `provider?: string | null`, set on every model call from its attempt (a string, or null when the body reported none) and left out on Jev calls, so a run.json made before reads as one. recordAttempts() passes it through hooks.call().

3. The run record (`harness/src/run.ts`). parametersOf() (run.ts:428) records `wordsModel: modelOf(options.model)` and `request: requestFor(modelOf(options.model)).name`, and `world: relative(REPO_ROOT, options.worldDir)` in place of the absolute options.worldDir (run.ts:431), where `REPO_ROOT = resolve(import.meta.dir, "..", "..")`, the checkout holding harness/, so a default run records `"world"`. runIdFor() (run.ts:271) and the separate mkdirSync (run.ts:450) are replaced by an exported `claimRunDir(corpusDir: string, startedAt: Date): { runId: string; runDir: string }`: it tries `mkdirSync(join(corpusDir, id))` (not recursive) for id = the base, then `<base>-2`, `<base>-3`, …, returns the first it created, takes an error whose `code` is `"EEXIST"` as taken and goes on, and rethrows every other error. No existsSync check precedes the mkdir, so the directory is claimed by the call that creates it and two processes can never be handed the same one. Committed runs are not rewritten.

4. The score (`harness/src/score.ts`). `scorePath(goalsPath, set, model)` (score.ts:210), still the one derivation, always names the model and its request: with `m = model ?? DEFAULT_MODEL`, `<set>.<modelSlug(m)>.<requestFor(m).name>.score.json`. A score with no model named therefore lands where a score naming the default does, and the plain `<set>.score.json` is never derived, written or read by score again; it stays as the committed record C9 reads (tests/rule.test.ts:17). score() records `model: modelOf(run.model)` and `request: requestFor(model).name` (score.ts:267-268). `GoalScore` gains `providers: { provider: string | null; calls: number }[]`, the run's model calls counted per reported provider in first-seen order; `ScoreFile` gains `providers` of the same shape, summed over perGoal in first-seen order.

5. The compare (`harness/src/compare.ts`). readScore() (compare.ts:126) refuses a score whose `request` is not `requestFor(model).name` for the model it is read for (compare.ts:139), naming the file, the request found and the one expected, so each side is read under its own model's request. `Comparison.request` is replaced by `requests: { baseline: string; candidate: string }`; the report is written to `<candidate slug>.<candidate request>.vs.<baseline slug>.<baseline request>.compare.json` and `.md` (compare.ts:289), a name no committed compare file has, and its header line names both requests. `Side` gains `providers: ScoreFile["providers"] | null`, null for a score file made before providers were recorded; the per-set table gains a `providers` column rendering each `<provider> <calls>` (an unreported provider as `unreported`), or `not recorded` when null. `GoalRun` gains `providers: GoalScore["providers"] | null`, taken from that side's score entry (null for an entry made before providers were recorded), never recounted from run.json, and each lost or gained goal's run line shows them.

6. The experiment copies and the comparison, run once in the job's worktree after the code above passes the gate, with the real endpoints and the registered thresholds. The four goal files corpus/goals/{calibration,blind-1,blind-2-spent,blind-2}.json are copied byte for byte to corpus/experiments/glm-default/, and a test asserts each copy's sha256 equals its corpus/goals original. Then: `bun run score --goals corpus/experiments/glm-default/calibration.json --sweep --tick-minutes 10` with no --model (the default), the same for blind-1, blind-2-spent and blind-2 without --sweep, then the four again with `--model anthropic/claude-haiku-5.5`, 94 runs into corpus/runs, then `bun run compare --baseline anthropic/claude-haiku-5.5 --candidate z-ai/glm-5.3-flash --goals` with the four copies. A goal whose target comes out unanswered (a Z.AI status refusal included) halts the comparison to the orchestrator, naming the run and its refusal, and is never counted or re-run until the orchestrator rules. If the reported cost of the scores passes $0.50 the run stops and goes to the orchestrator. The eight score files, their runs, the two compare files and the four copies are committed together; every file under corpus/goals stays byte-identical. The lane's result reports per set each model's reached count, retries and providers, and the losses and gains from the compare.

7. Tests (strata-side under tests/, over tests/stand-ins.ts, whose model stand-in gains an optional provider in its answer body). The request: a run with no --model posts z-ai/glm-5.3-flash with exactly arm F's body for target and words and records request json-object-z-ai-retry; a run with --model anthropic/claude-haiku-5.5 posts a body whose JSON text equals today's json-schema-retry body text and records json-schema-retry; an unlisted model gets json-schema-retry; both names are pinned beside their bodies, so a change to a body that keeps its name turns a test red. The provider: a model call whose body carries provider Z.AI records it, one whose body has none records null, a Jev call has no provider key; score sums providers per goal and per file; compare renders the providers column and `not recorded` for a score without them. Compare: GLM under json-object-z-ai-retry beside Haiku under json-schema-retry is accepted and written to the two-request name; a score at the right path whose request is not its model's is refused, writing nothing. The score path: a score with no model named writes `<set>.z-ai_glm-5.3-flash.json-object-z-ai-retry.score.json` and leaves a pre-written `<set>.score.json` byte-identical, as do scores under named models. The race: several child processes claim run directories for the same startedAt in one corpus at once; every claim succeeds and every directory is distinct; with the existsSync-then-mkdir form restored the test goes red. The world: a run's run.json has `parameters.world` `"world"` and no string value anywhere in it for which path.isAbsolute holds. The copies: each corpus/experiments/glm-default goal file's sha256 equals its corpus/goals original. M1, M3, S2 and H6 are updated to these; C9 runs unchanged.

Acts on the gap: The gap is that the harness cannot ask one model by a request of its own, records no provider, and claims run directories non-atomically. The request table gives each model its own request, with GLM's arm F as the listed entry and today's request for every other model; the attempt carries the reported provider into run.json, the score and the compare; and the mkdir claim makes the directory's creation the claim. With the default set to GLM and the score path always naming model and request, the decided default can be set and measured like for like without writing over any committed record.

Acts on the gap: The gap is that the harness cannot ask one model by a request of its own, records no provider for a model call, and claims run directories non-atomically. A request table keyed by model, with GLM's arm F body listed and today's json-schema-retry for every other model, meets the first; the attempt's reported provider carried through run.json, the score and the compare meets the second; and a claim made by the mkdir that creates the directory meets the third. DEFAULT_MODEL then becomes GLM, and a score path that always names model and request lets the switch be made and measured like for like without writing over any committed record.

## Commitments

- With no model named, the target and the words are asked of z-ai/glm-5.3-flash by json_object with provider order [z-ai] and allow_fallbacks false, under the request name json-object-z-ai-retry, recorded in run.json and the score.
- Every model not listed in the request table, anthropic/claude-haiku-5.5 included, is sent a body whose JSON text equals today's json-schema-retry body, under the name json-schema-retry.
- Every model call in a new run.json records the provider OpenRouter reported for it, or null when it reported none; each score entry and file counts model calls per provider, and the compare shows providers per set and per moved goal.
- compare reads each side under its own model's request, refuses a score whose request is not its model's, and writes to a name carrying both requests, never a committed compare file's name.
- A run directory is claimed by the mkdir that creates it, retried on EEXIST, so concurrent score processes each get their own and none fails.
- run.json records world relative to the repository root, and no new run.json carries an absolute path; committed runs are left as they are, and #8 closes with this work order.
- A score with no model named lands on the default's named path; no score or compare writes any file under corpus/goals, and C9 still reads the committed calibration.score.json.
- GLM (no --model) and Haiku are each scored once per set on byte-identical copies of the four goal files under corpus/experiments/glm-default/ and compared there, a test pins each copy's sha256 to its original, an unanswered target halts for a ruling, and spend past $0.50 stops for the orchestrator.
- The prompts, the parse and the one identical retry are unchanged; the harness still imports nothing from the engine or the server.

## Sacrifices

- allow_fallbacks false means a Z.AI outage or refusal stops every default run with a status refusal instead of routing GLM to another provider. (0 of 191 corpus/experiments/glm-request/F/calls.jsonl, arm F's model calls pinned to Z.AI with no fallback, those not answered 200)
- Z.AI has no structured_outputs, so GLM's request asks for any JSON object and relies on the prompt for the shape, with zod and the one retry as the only check of it. (0 of 141 corpus/experiments/glm-request/analysis.json, arm F's runs lost to a schema failure)
- The plain <set>.score.json files are never written again, so the calibration record C9 reads can no longer be refreshed by a model-less score; a new calibration (#6) must name its own writer. (6 of 22 git ls-files corpus/goals/*.score.json, the committed plain score files)
- The new compare cannot regenerate the committed json-schema-retry or pre-request compare reports, whose names carry one request or none; they stay committed as they are. (4 of 4 git ls-files corpus/goals/*.compare.*, the committed compare files)
- Score files made before providers were recorded show `not recorded` in the compare's providers column. (22 of 22 git ls-files corpus/goals/*.score.json, committed score files without providers)
- A world outside the repository is recorded as a relative path climbing out of it, which names directories above the checkout. (0 of 976 corpus/runs/*/run.json, committed runs whose world is not the world folder at a checkout's root)
- The experiment folder holds copies of the four goal files, kept equal to corpus/goals only by the sha256 test. (not a case: The four copies are pinned to their corpus/goals originals by a sha256 test the gate runs, so a drifted copy cannot pass the gate and never reaches a score.)
- The request table is keyed by exact model id, so another GLM id, a later version included, is asked by json-schema-retry until it is listed. (0 of 976 corpus/runs/*/run.json, committed runs asked of a z-ai model other than z-ai/glm-5.3-flash)

## Risk

If Haiku's body changed by a key, a value or its order, the committed json-schema-retry scores would no longer be like for like with new ones under the same name; a test compares the body's JSON text with today's. If GLM's request kept require_parameters or a json_schema format, the Z.AI pin would leave no endpoint and every default run would be refused; it is arm F's body exactly. If scorePath kept the plain path for no model, a default score would write GLM's runs over C9's calibration record and the other plain records; it always names model and request, and a test keeps a pre-written plain file byte-identical. If compare kept one request, it could not set GLM beside Haiku at all, and if it read a score without checking its request it could set unlike runs side by side; it checks each side against its own model's request. If the run-directory claim kept an existence check before the mkdir, two processes could still be handed one id; the mkdir is the claim. If world stayed absolute, every new run would leak the home path #8 names; a test scans run.json for absolute paths. If the re-scores ran beside corpus/goals, Haiku's would write over the four committed Haiku files the committed json-schema-retry report names; they run on copies in the experiment folder.
