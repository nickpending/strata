# Design: npc-knowledge

## Purpose

Every person in the world knows things as of a tick: the places authored for it and the people it has ties to as of boot, and from each event copy it receives the locations of the people and the holders of the items that copy shows, an arriver's copy naming everyone already in the room; the engine keeps those facts as append-only rows beside the copies, the bench shows each person's latest facts with tick, source and a god's-eye stale marker, and the Jev player can be given and scored on a goal that someone knows where a person is or who holds an item now.

## Form

Facts as rows beside the witnessed copies, taught by the registry, read latest per subject, served on one route, shown in one panel section and checked by one new end state.

1. Fact kinds (`src/engine/knowledge.ts`, new). One table `factKinds`, the one home of each kind: `location` (thing a person, value a `Location` as things.ts:19-21 types it, current value `snapshot.people[thing].location`), `holder` (thing an item, value a person id, current value `snapshot.items[thing].holder`) and `place` (thing a room, value null, current value null: rooms are definitions and never change). A fact is `{ kind, thing, value }`; a known row is a fact plus `witness`, `tick` and `event` (the teaching event's id, or null for an authored fact). The `Fact` type lives where no import cycle forms (the gate's cycles check), so events.ts can name it.

2. Who an arriver finds (`src/engine/events.ts`, `src/engine/clock.ts`, `src/engine/engine.ts`, `src/engine/pending.ts`). The `physical.arrive` payload gains `present: id[]`, the people located in the room it arrives in, sorted, the mover not among them, and its visibility narrows `present` to participants, `{ audience: "place", narrow: { present: "participants" } }`: the mover's copy carries it and a bystander's copy drops it through redact() (events.ts:126-134), since rudy's decision is that the arriver learns who is there, not that a bystander learns it from someone else's arrival. Presence is public world state (strata-layered-world-engine.md:102), so the field carries nothing any witness may not hold. `present` is set when the clock fires the arrive, never at depart: the schedule entry keeps `{ from, to }` (its `Scheduled` payload is the arrive payload without `present`, clock.ts:6-9), and clock.ts gains `fired(entry, tick, snapshot)`, the one place a due entry becomes a draft, which for an arrive sets `present` from `snapshot.views.presence[entry.place]` less the mover and for a lapse returns the entry's payload as today. `Engine.step()` (engine.ts:137-147) calls it for each due entry with the snapshot as it stands just before that entry is recorded, so a second arrive at the same tick and room finds the first mover there; pending.ts's due after (pending.ts:106) calls it with the snapshot it already builds, where `present` changes no reducer and so no after. `dueDrafts` keeps returning the due entries, in schedule order, to both. The fuzzer's state replay (replay.ts:18) applies logged events, whose payloads already carry `present`, so it needs no change for the field; section 9's projection checks it.

3. Teaching (`src/engine/events.ts`, registry at events.ts:23). `RegistryEntry` gains a required `teaches: (copy: Copy) => Fact[]`, so no subkind can be added without saying what its copies teach. Each reads only the copy it is given, its envelope (actor, targets, place) and its payload; none reads a field the registry narrows. The entries: `physical.depart` teaches the actor's location `{ transit: { from, to, arrivesAt } }` from its payload; `physical.arrive` the actor's location `{ room: to }` and, for each person its copy's `present` names, that person's location `{ room: to }`; `speech.say` the actor's location `{ room: place }`; `speech.say-to` and `speech.whisper` the actor's and each target's location `{ room: place }`, since the rule requires the target in the room (rules.ts:182-195); `exchange.offer` the actor's and the target's location `{ room: place }` and the item's holder, the actor; `exchange.accept` the actor's and the target's (the giver's) location `{ room: place }`, since accept requires the giver present (rules.ts:163-166), and the item's holder, the actor; `exchange.refuse` the actor's location `{ room: place }` and the item's holder, `from`, and not the giver's location, since refuse does not require the giver present; `exchange.lapse` the item's holder, `from`, and no location, since the clock fires it at the offer's room whoever has since left (clock.ts:52); `time.tick` nothing. `learned(copy, witness)` in knowledge.ts is the entry's facts less those the witness's own parts own: a location fact whose thing is the witness, and a holder fact whose value is the witness.

4. Rows (`src/engine/store.ts`). The schema gains `known (seq INTEGER PRIMARY KEY, witness TEXT NOT NULL, kind TEXT NOT NULL, thing TEXT NOT NULL, json TEXT NOT NULL, tick INTEGER NOT NULL, event TEXT, FOREIGN KEY (event, witness) REFERENCES witnessed (event, witness))`, so a taught row can only stand beside a copy its witness holds, and a view `known_latest` holding, per (witness, kind, thing), the row of greatest seq. Rows are only inserted: no update or delete statement touches `known`. `Store.create(path, rows, known)` writes the authored rows in the same build-then-rename transaction as the state rows (store.ts:43-66); `know(row)`, `known(witness)` (every row in seq order) and `latestKnown(witness)` (the view's rows, in seq order) are added.

5. Boot (`src/engine/definitions.ts`, `src/engine/knowledge.ts`, `world/people/*.toml`). `personSchema` gains a required `places: z.array(id)`; `checkReferences` refuses a place that names no room, rule `place-names-room`, path `places.<i>`. `initialKnown(defs)` is one row per place per person: kind `place`, thing the room, value null, tick 0, event null. Ties are not written as rows: the ties part already owns them (things.ts:39). Each of glitch.toml, mux.toml and rogue.toml authors `places = ["back-room", "chrome-cassette"]`, both rooms of the two-room world.

6. The apply path (`src/engine/engine.ts`, record() at engine.ts:157). In the witness loop, after `store.witness(event.id, witness, copy)`, each fact of `learned(copy, witness)` is appended with the event's tick and id, inside the same transaction; a refused or invalid action records no event, so it writes no row. `Engine.knowledge(person)` returns the `KnowledgeView`: `own`, the person's location from the location part and its holdings from the snapshot's holdings view; `people`, each tie target as of tick 0 with source authored, then each other person named as actor or target of a copy the person holds, in the order first received, with that copy's tick and event id and subkind (a tie target stays authored); `facts`, the `known_latest` rows less any holder fact about an item the person holds now (the holder part owns it while it is held), each with `tick`, `source` (the event id, or "authored"), `subkind` (the teaching event's, or null), `now` (the factKind's current value in the snapshot) and `stale` (whether value and now differ, by `Bun.deepEquals`); and `history`, every row in seq order with the same tick, source and subkind and no stale. Nothing in the engine's apply or rule path reads `stale` or `now`: they are the operator's view.

7. The route (`src/server/routes.ts`). `GET /api/knowledge/<person>` answers `KnowledgeBody = KnowledgeView` built with `satisfies`, 404 naming a non-person and 400 on malformed percent-encoding, exactly as /api/received/<person> (routes.ts:133-138). bench/app.js's api gains `knowledge(thing)`.

8. The panel (`bench/panels/knowledge.js`, new; `bench/panels/world.js`). world.js's refresh reads the knowledge of every person beside the snapshot, and render places a Knowledge section after Items, drawn by knowledge.js's `knowledgeSection(h, bodies)`: an h2 `Knowledge`, then per person a block headed at level 3 `What <name> knows`, with no parentheses, so vocabulary()'s room pattern (target.ts:117) never reads it, and these list lines, each opening with its label: `own location (location part): room <id>` or `own location (location part): in transit <from> -> <to>, arrives tick <n>`; `own holdings (holder part): <ids>` or `nothing`; `knows person <id>: authored tie, boot` or `knows person <id>: first experienced tick <n>, <event> <subkind>`; `knows place <id>: authored, boot`; `location of <id>: room <room>` or `location of <id>: in transit <from> -> <to>, arrives tick <n>`, then `, learned tick <n> from <event> <subkind>`; `holder of <item>: <person>, learned tick <n> from <event> <subkind>`; and on a stale fact a marked span ` STALE (operator view): now <current value in the same words>`. No line has the form `<id>: held by`, which vocabulary() reads as an item (target.ts:116), nor `exits:`. The section adds no control, so it adds no candidate (candidates.ts:23) and no unlabeled control.

9. The replay oracle and the truth check (`src/driver/replay.ts`, `src/driver/run.ts`). `projectKnown(defs, tickMinutes, events)` replays the log as record() does, from `initialKnown(defs)`: each event applied through every part, its witnesses found from the snapshot after it (witnessesOf), each copy redacted and `learned`; it returns the rows it reaches, every `false` fact, one whose value differs from its factKind's current value in the snapshot right after its teaching event, and every arrive whose `present` is not exactly the people in its room just before it, sorted, the mover not among them. The driver's replay check fails on the first row where the live store's `known` rows of every person (by witness, then seq order, compared without seq) differ from the projection, or on any false fact or wrong `present`, naming the witness, the event and both values; it runs at every point the state replay runs today.

10. The harness (`harness/src/bench.ts`, `goal.ts`, `target.ts`; `src/adapter/contract.ts`). bench.ts declares `KnowledgeBody = { person: string; facts: { kind: string; thing: string; stale: boolean }[] }` and contract.ts checks routes.ts's body against it. goal.ts gains `knowsSchema = { knows: { person, location: <person> } | { person, holder: <item> } }`, in both `endStateSchema` and `expectSchema`; `holds()` for it reads `/api/knowledge/<person>` and is true only when a fact of that kind (`location` or `holder`) and that thing stands with `stale` false, so an absent or stale fact never holds; `satisfies()` is false for it, as for said, since a pending after carries no knowledge; `described()` reads `<person> knows where <thing> is now` and `<person> knows who holds <item> now`. target.ts's `namesOf` checks the knower and a location's thing against the people and a holder's item against the items; the prompt lists the two end states, `{"knows": {"person": "<person>", "location": "<person>"}} (the first person knows where the second is now)` and `{"knows": {"person": "<person>", "holder": "<item>"}} (the person knows who holds the item now)`, and one sentence of how people learn: a person learns where someone is only while in the same room when that someone arrives, leaves, speaks, is spoken to, offers or accepts there, and who holds an item when it is offered, accepted or refused in their room; arriving somewhere teaches the arriver where everyone already there is, and what someone learned goes stale when it changes out of their sight. Nothing else in the rule, the thresholds, run.json or any score field changes.

11. The goal set (`corpus/goals/knowledge.json`, new), author `claude-opus-5-5 (npc-knowledge shaper)`, six goals: `mux-finds-rogue` "Mux has never laid eyes on Rogue. Get him to find out where she is." knows mux location rogue; `rogue-finds-mux` "Rogue wants to know where Mux is. Make sure she finds out." knows rogue location mux; `glitch-finds-cell` "Glitch needs a charge cell. Let him learn who has one." knows glitch holder charge-cell; `mux-sees-glitch` "Mux should know where Glitch is right now." knows mux location glitch; `mux-finds-shard` "Mux has heard of a data shard. Let him find out who holds it." knows mux holder data-shard; `rogue-reads-glitch` "Make Rogue know what Glitch is really thinking." outcome no-such-action. No goal's end state holds on the fresh world, since no location or holder fact exists at boot.

12. Tests. Engine (tests/knowledge.test.ts, new): a fresh boot gives each person exactly its authored places and tie people and no location or holder fact; each subkind's teaching on a hand-built world (a whisper teaches a bystander the whisperer's and the target's room and no words; a refuse teaches no giver location; a lapse after the giver left teaches the holder and no location; an arrive teaches the room's people the mover's room and teaches the mover the room of each person already there, while a bystander's copy carries no `present` and teaches it nothing of the others; two arrivals into one room at one tick give the second mover the first in `present`; an arrive into an empty room has `present` empty); no row about a witness's own location or its own holding; latest per subject after two facts, with the earlier one in history; a refused and an invalid action leave the rows unchanged; a fact goes stale when its subject moves out of sight and the stale fact still holds its tick and source; a row naming an event its witness holds no copy of is refused by the foreign key; a definition with a place naming no room refuses boot naming `places.0` and `place-names-room`. Fuzzer (tests/driver.test.ts): seeded runs pass the knowledge replay and truth check, and a planted false teaching (a test-only registry whose say teaches the target's location wherever it is) fails it. Server (tests/server.test.ts): the route's body, 404 and 400. Page (tests/page.test.ts): the fresh bench page has no unlabeled control and the same controls as before the panel, and vocabulary() over it gives the same people, items, rooms and exits as the world defines, both on the fresh world and after a fact exists. Harness (harness/test/): holds() for knows against a stand-in route, true for a fresh fact, false for a stale one and for an absent one; checked() refuses a knows end state naming an unknown person or item; satisfies() is false for knows. Strata-side (tests/player.test.ts): a run on a hosted bench whose model stand-in types `knows mux location glitch` with steps glitch depart east then the clock reaches the arrive ends reached, and its run.json, events and received files are as any reached run's.

13. Real runs, after the code passes the gate, with the default model (z-ai/glm-5.3-flash, json-object-z-ai-retry) and the run list and cost sent to the orchestrator first: `bun run score --goals corpus/goals/knowledge.json --tick-minutes 10` (6 goals), and `bun run score --goals <set> --tick-minutes 10` for blind-1, blind-2 and blind-2-spent (38 goals), whose score files land at new `<set>.z-ai_glm-5.3-flash.json-object-z-ai-retry.score.json` paths and overwrite no committed file, as a check that the larger page and the longer target prompt cost the existing sets nothing; their baseline is arm F of corpus/experiments/glm-request, the same model and request before this change. calibration is authored by the rule's author and is scored only with --sweep, which this work does not run. Every goal not reached is named in the results with its cause, read from its run's loops.jsonl and run.json; a loss a code path decided (a vocabulary or checked() refusal, holds() misreading the route) is a defect fixed before merge, and a loss in the model's or Jev's answers is reported as such.

Acts on the gap: It supplies the record the gap names: each person's facts as rows with tick and source, written as each copy lands and from boot, read latest per subject on a bench route, shown with a stale marker in a Knowledge section, and checked by a knows end state the Jev player can be given and scored on, so what an NPC knows, as of when, can be seen, tested and scored against the world.

## Commitments

- Every fact a person knows is an append-only row naming its tick and its source, the teaching event or authored at boot, and no row is ever updated or deleted.
- What each subkind's copies teach is declared once, in its registry entry, and is required for every entry.
- An arriver learns the room of every person already in the room it arrives in, as of the arrive tick, from its own copy, whose `present` is set when the clock fires the arrive; a bystander's copy drops it.
- A taught fact is derived only from the witness's own redacted copy and is written in the same transaction as that copy, and the store refuses a taught row with no copy beside it.
- Every fact matched the world at the tick that taught it, checked by the fuzzer's replay over every seeded run.
- Knowledge holds no fact about a person's own location or an item it holds now; those are read from the location and holder parts, and ties from the ties part.
- A reader gets the latest fact per (fact kind, thing), and every earlier fact stays readable in order.
- The bench serves each person's knowledge on one route and shows it in a Knowledge section with tick, source and a stale marker, adding no control and no text the target's vocabulary reads.
- A knows goal holds only when the knower's latest fact on that subject is not stale; an absent or stale fact never holds.
- The harness reads knowledge only over the bench route and imports nothing from the engine or the server.
- Nothing in the engine's rules or apply path reads whether a fact is stale.
- Real runs use the default model, overwrite no committed score file, and their cost is named to the orchestrator before any is spent.

## Sacrifices

- A bystander already in a room learns nothing about the others there from someone else's arrival, since `present` is narrowed to the arriver; it learns them when they act or are addressed. (171 of 502 physical.arrive events in corpus/runs/*/events.jsonl with two or more non-movers holding a copy in received.jsonl)
- A refuse teaches nothing of the giver's location, and a lapse teaches nobody's location, since neither event guarantees who is in its room. (3 of 2904 exchange.refuse and exchange.lapse events among all events in corpus/runs/*/events.jsonl)
- Speech teaches only where its speaker and its addressee are; nothing said is learned as a fact, since being told is the gossip block's. (427 of 2904 speech events among all events in corpus/runs/*/events.jsonl)
- Every person's authored place list is both rooms of the two-room world, so place knowledge distinguishes no one yet. (not a case: Authored content of three definition files, not a path any run or reader exercises differently.)
- No decision reads knowledge yet; how it enters an NPC's snapshot waits for the mind and plan blocks. (not a case: No decision path exists yet that could read it; the deferral is the exploration's (npc-knowledge.md Deferred).)
- A knows end state is never served by a pending state's resolution, since a pending after carries no knowledge; the rule reaches it only through the plan's steps or Jev's choice. (not a case: No committed goal has a knows end state; it bites only the new knowledge set, whose runs report it.)
- Every loop's page text, read by Jev and by the target call, grows by the Knowledge section, and every target prompt by the two knows end states and the sentence on learning. (7447 of 7447 loops in corpus/runs/*/loops.jsonl, each of which reads the page)
- Committed runs' events.jsonl hold arrive events without `present`; they are history read as files, never re-parsed against the registry, and are not rewritten. (502 of 2904 physical.arrive events among all events in corpus/runs/*/events.jsonl, each committed without present)

## Risk

If `present` were set at depart, it would name who was there when the mover left, not when it arrived; it is set by fired() just before the arrive is recorded, and the replay check compares it with the room's presence then. If `present` went to every witness, a bystander would learn the others from an arrival it did not make, a change rudy did not decide; it is narrowed to the mover. If teaching read the event instead of the copy, a whisper's bystander could learn what the copy withholds; teaches is handed only the redacted copy. If refuse or lapse taught locations, a fact could be false at its own tick, which the fuzzer's truth check would catch on a seeded run that walks a giver away; the entries leave those out. If the own-holding filter ran only at write, a person who accepted an item would show its giver's stale holder fact; the read also hides holder facts about items the person holds now. If the panel wrote `<item>: held by` or a level-3 heading ending in an id in parentheses, vocabulary() would add false items or rooms to every target; the lines avoid both and a page test pins the vocabulary. If the harness compared fact values with the snapshot itself, the stale comparison would have two homes; it reads the bench's stale. If the regression scores were written to the committed GLM score paths they would overwrite history; the default request's paths are new. If knowledge were rebuilt by replay on read, the log would be read on every request; rows are written as events land and replay is only the fuzzer's oracle.
